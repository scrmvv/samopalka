# Этап 3.3 — дополнительные слова и эффекты

**Основа:** принятая сборка 3.2 (28.10.2026) со всеми её хотфиксами. Это тестовая реализация расширенной боевой логики, не полный релиз всей настольной игры.

## Какие правила подключены

| Слово / свойство | Реализация в 3.3 |
|---|---|
| Удар, Лечение, Щит, Мана | Базовые операции 3.1, сохранены; сложные атаки используют реальные числа из карточек |
| Яд | Накладывается на цель; урон в конце её хода обходит щит; сохраняется до смерти или очищения (очищение как действие будет в 3.4) |
| Регенерация | В начале хода лечит, взаимно уменьшает действие Яда; поддерживается серверным движком |
| Слабость | Уменьшает значение всех непустых сторон на N; после хода жертвы снимается |
| Гниение | Уменьшает использованную сторону на 1 за каждое применение. Не снимается само по себе |
| Сон, Оглушение, Паралич | Сон запрещает ход до следующего фактического урона; оглушение пропускает ход; паралич добавляет «Боль» к следующему действию |
| Уворот, Броня, Прочность | Уворот целиком отменяет N ударов; броня уменьшает каждый «Удар»; прочность ограничивает урон за попадание единицей |
| Бесплотность | Не более одного успешного удара по цели до её следующего хода |
| Дальность, Позади | Дальнобойная грань Лучника игнорирует ограничения дистанции; противники с «Позади» защищены своими передними союзниками |
| Разброс, Все герои | Цель удара расширяется на соседние сущности или всех живых героев |
| Издыхание, Пиявка, СамоЛечение, Боль | Усиление ударов при малом здоровье атакующего, бонус за потерянное HP цели, лечение атакующего и самоурон |
| СамоУворот и Самощит + Насмешка | Реализованы стартовые особые грани Берсерка и Рыцаря; Насмешка переносит монстра к рыцарю |
| Окаменение Горгоны | Использованная против Горгоны грань становится пустой до смерти героя / будущего очищения |
| Призыв / перемещение / смерть | Указанные на карточках призывы врагов, перемещение Труповозки, посмертная атака Гнильца, гибель Миазма |
| Чума / Лич | Прокажённый снижает максимальное HP героев; Лич один раз призывает противников при половине здоровья |

**Оговорка по нескольким формулировкам:** там, где печатная карточка оставляет пространство для трактовки (например, порядок сложных одновременных эффектов или «Цель: случайный» без локации), в MVP используется определённая последовательность серверных действий. Перед финальной балансировкой эти случаи нужно проверить с автором игры. Перемещаемые и призванные враги могут делать поле более плотным; они расставляются вдоль внутреннего круга.

## Что намеренно не входит

- Получение и применение артефактов, редактирование и прокачка граней кубика — **3.4**.
- Роли и их скрытые способности — **3.5**, после обновлённой редакции заказчика.
- Полная реализация оставшихся слов, встречающихся только в артефактах и расширенных комбинациях: «Финт», «Витальность», «Воскрешение», «Эго», «Рост», «Энергия», «Очищение», «Перезарядка», «Усиление», «Скорбь» и др. Их необходимо подключать к редактору сторон и базе артефактов.
- Локации, общий чат, публичное размещение и сохранение партий (не входят в текущий MVP).

## Сценарий проверки

1. Запустить новую комнату с 2–4 игроками, убедиться, что стартовое лобби и сеть работают как раньше.
2. Выбрать Берсерка. При выпадении третьей грани «СамоУворот 1» первый удар монстра должен отмениться; во втором ударе уворота уже нет.
3. Выбрать Рыцаря. При выпадении грани «Самощит + Насмешка» выбрать монстра другого героя. Убедиться, что щит добавлен, монстр переходит к рыцарю и теперь отвечает ему.
4. Выбрать Лучника. При выпадении стороны «Удар + Дальность» проверить возможность выбора далёкого монстра и босса.
5. На этажах 2+ проверять Яд: он должен сработать в конце хода отравленного, даже при щите. «Слабость» временно уменьшает значения кубика.
6. Проверить врагов с «Бронёй», «Прочностью» и «Бесплотностью»: одинаковый удар снимает им разное количество HP.
7. Проверить, что при появлении дополнительных монстров из призыва они не накладываются на босса.
8. Дойти до привала и следующего этажа. Прежние монстры не должны остаться на поле, а новые эффекты должны синхронизироваться в браузерах игроков.
9. Проверить исходные возможности 3.2: выход, переподключение, автоматическую смену хода, работу таймеров и журнал.

## Как установить поверх принятой 3.2

1. Остановить сервер (`Ctrl+C`).
2. Распаковать архив `samopalka_stage3_3_patch.zip` в корень проекта **с сохранением структуры каталогов** и заменой файлов.
3. Пересобрать проект (из корня, где находится `package.json`):

```powershell
npm.cmd run build
npm.cmd test
npm.cmd start
```

На macOS/Linux используйте `npm` без `.cmd`. Повторно устанавливать зависимости не нужно, если уже установлен актуальный `node_modules`; в новом каталоге сначала выполняется `npm install`.

4. Создать **новую партию**. Состояние старых комнат не сохраняется между перезапусками сервера. Для других участников перезагрузить страницу (`Ctrl+F5` или `Cmd+Shift+R`).

Тестовые таймеры — 60/60 секунд, как в прежней сборке. Перед финальной сдачей верните `TURN_SECONDS=15` и `SHORT_TURN_SECONDS=5`.

## Проверки реализации

- **64/64** автоматических серверных теста прошли в изолированной компиляции TypeScript (без npm-зависимостей): прежние проверки лобби, боя и поля плюс новые проверки эффектов.
- Проверка типов серверного движка прошла; изменённый клиент прошёл синтаксическую проверку TSX.
- **Не подтверждено:** полный `npm run build` на оригинальных зависимостях, реальный мультиплеер и отображение в браузере. Это необходимо протестировать локально.
