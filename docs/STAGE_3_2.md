# Этап 3.2 — очередь противников, этажи и конец партии

## Что добавлено

- После действия героя (включая пропуск) атакуют **живые монстры напротив него**.
- После хода последнего игрока в круге атакует **общий босс**. Ходы, расчёты и цели назначаются на сервере.
- Учитываются атаки противников, здоровье, щит, смерть и переход монстров к следующему живому игроку по часовой стрелке.
- Монстры и боссы выбираются из соответствующего этажа по таблице **«Монстры»**: используются их **названия, HP, этаж и число карт в колоде**.
- Базовая досягаемость: собственный монстр, монстры соседей и соседние герои; босс доступен после гибели всех монстров **напротив самого героя**. Расширения дальности будут в 3.3.
- После гибели всех противников наступает **привал**. Хост нажимает кнопку перехода на следующий этаж.
- На привале герои восстанавливают **2 + d6 здоровья** (не выше максимума); погибшие в этой битве герои возвращаются в отряд. Щиты и мана сохраняются.
- После зачистки шестого этажа игра завершается победой отряда. По ранее согласованному MVP игра также заканчивается победой, если остаётся один живой герой; при смерти всех — поражением.
- Панель результата показывается всем игрокам синхронно; ходить во время привала и после окончания нельзя.

## Важные ограничения (не полная реализация правил)

**Эффекты монстров из исходной таблицы ещё не реализованы полностью.** Для монстров с однозначным «Удар, N» применяется указанное значение. Для монстров со сложными словами (например, «Удар, Яд, 1», «Разброс», «Гниение», «Паралич», «Все герои; Лечение…») временно применяется тестовая базовая атака **1**, что прямо отмечается в журнале. Для «Удар, Все герои, N» базовый урон по всем живым героям работает, но дополнительные слова не работают. Это сознательная временная модель для тестирования очереди, а **не заявка на реализованный баланс**.

**Награды и артефакты после этажей ещё не выдаются**: они входят в 3.4. После привала можно пройти дальше без наград и проверить весь цикл из шести этажей. Локации исключены из MVP по просьбе заказчика. Скрытые роли отложены на 3.5.

В таблице **«Правила»** конец партии определяется гибелью/бегством всех героев либо шестым этажом. В более позднем согласовании MVP также указана победа последнего выжившего. Пока реализовано это позднее согласование — автоматическая победа при одном живом герое. Если подразумевается другое поведение (например, продолжение PvE в одиночку), оно требует уточнения.

## Проверка

1. Создать комнату с 2–4 героями, начать игру. Убедиться, что у каждого свой противник с названием и здоровьем.
2. Ударить монстра. После завершения хода монстр должен атаковать героя напротив себя; щит поглотит урон первым.
3. Пропустить ход: ответная атака монстра всё равно должна произойти.
4. Дождаться хода последнего игрока в круге: только **после него** босс наносит удар, затем начинается новый круг.
5. Уничтожить монстра напротив себя: босс становится допустимой целью, если за героем не осталось других назначенных ему монстров.
6. Уничтожить всех врагов: появится окно **«Этаж пройден»**, только хост может продолжить. Переход создаёт новых монстров и восстанавливает здоровье.
7. Пройти до шестого этажа: появится конечный экран с победой.
8. Проверить гибель героя и выбор следующего монстра: после гибели он переносится к следующему живому герою по часовой стрелке.
9. Сравнить поле и журнал в двух браузерах, затем обновить один браузер. Состояние должно совпадать.

## Установка патча поверх 3.1

Остановить игровой сервер; распаковать содержимое архива патча в корень проекта **с сохранением путей** и заменой одноимённых файлов. Затем:

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

Открыть игру заново, создать **новую** комнату и новую партию. Старое состояние из памяти сервера после обновления не восстанавливается.

Тестовые таймеры по умолчанию — 60/60 секунд. Для согласованных 15/5 перед `npm.cmd start` задать:

```powershell
$env:TURN_SECONDS='15'
$env:SHORT_TURN_SECONDS='5'
```

## Проверка исходников

Локально выполнены 32 серверных проверки в независимой сборке TypeScript без загрузки npm и дополнительная проверка типов серверного движка. Полная установка клиентских зависимостей и запуск графического интерфейса с Socket.IO **не проверены в этой среде**, поэтому финальную npm-сборку и сетевую проверку нужно выполнить на компьютере разработчика.
