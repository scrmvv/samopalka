# Самопалка — этап 4.1–4.2: админка и баланс персонажей

База: `samopalka_3.4.4_RUNTIME_FIXED_FULL.zip`. Этот патч не закрывает ранее оставшиеся замечания по 3.4.4 и не включает этап 4.3–4.4. Изменения предназначены для отдельной ветки разработки.

## Что реализовано

- `/admin` — отдельный React-экран, не подключающий игровой сокет; авторизация по паролю, сессионная HttpOnly-cookie, выход.
- 6 героев: HP, лимит маны при завершении хода и числовая сила каждой из шести исходных граней. Пустые грани остаются пустыми; слова и типы не редактируются.
- 34 противника (монстры и боссы): HP, числовая сила основной грани (если она есть). Сила составной грани по существующим правилам влияет на связанные эффекты. Поиск и фильтр по этажу.
- Доступные индивидуальные параметры: броня, самоуворот, прочность, пиявка, чума, посмертный удар/яд, рост, гниение и множитель издыхания. Все подключены к существующим обработчикам. Способности без реализованной числовой логики не получают фиктивные редакторы. Призывы, условия срабатывания, типы эффектов, количество карт в колоде, скрытые роли, новые сущности не редактируются.
- Сброс параметров отдельной карточки в черновике, сохранение общим действием, отмена несохранённых изменений. Сервер повторно проверяет весь объект, неизвестные ID и поля не принимаются.
- Сохранение в `data/balance.json` (или абсолютный путь `BALANCE_FILE`), атомарная замена файла, предыдущая версия в `balance.json.bak`, защита от перезаписи чужой ревизии.
- Новые партии получают актуальный баланс; текущая партия хранит собственную копию, в том числе для будущих этажей, призывов и тестовой панели. Лобби обновляют отображаемый HP при сохранении. После завершения партии и повторного старта используется новая ревизия.

## Запуск на Windows (PowerShell)

Для локального тестирования распакуйте полный архив в отдельную папку либо примените PATCH поверх **точно** предыдущего `3.4.4_RUNTIME_FIXED_FULL`. В корне:

```powershell
npm install
npm run build
npm test
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

В `.env` задайте собственный `ADMIN_PASSWORD` (не менее 12 символов), `ADMIN_ALLOW_HTTP=1` и `HOST=127.0.0.1`. Сохраните файл, затем:

```powershell
npm start
```

Откройте `http://localhost:3000/admin`. Введите выбранный пароль. Корневой `.env` автоматически загружается при старте сервера, в том числе при `npm run dev:server`. При запуске Vite отдельно открывайте `http://localhost:5173/admin` (его прокси ожидает сервер на порту 3000). Переменные, заданные в PowerShell или systemd, имеют приоритет над файлом; изменение `.env` требует перезапуска сервера. Для тестирования через несколько устройств не открывайте HTTP-админку в общую сеть; используйте HTTPS.

Проверка вручную: измените HP Воина с 11 до 20, сохраните, проверьте новое лобби и начало новой партии; старая партия должна остаться без изменений. Измените силу грани и HP монстра, проверьте на новой партии; перезапустите сервер и убедитесь, что параметры сохранились. Сбросьте карточку и сохраните исходные параметры.

## Развёртывание на VPS

Требуется HTTPS через доверенный локальный reverse proxy, пересылающий `X-Forwarded-Proto: https`. Не используйте `ADMIN_ALLOW_HTTP=1` на публичном сервере. Без `ADMIN_PASSWORD` длиной не менее 12 символов админка отключена (сама игра работает). Можно создать `/opt/samopalka/.env` с правами `0600` для пользователя сервиса `samopalka` и задать в нём пароль. Если используется штатный systemd-unit, заданные в нём `HOST`, `PORT`, `DEBUG_TOOLS` имеют приоритет над `.env`: для публичного размещения обязательно переопределите `DEBUG_TOOLS=0`. Альтернатива — установить пароль через защищённый файл переменных окружения, например `/etc/samopalka-admin.env` с правами `0600`, принадлежащий root. Не коммитьте пароль. Пример systemd drop-in:

```ini
[Service]
EnvironmentFile=/etc/samopalka-admin.env
```

В файле окружения задайте `ADMIN_PASSWORD` своим случайным длинным паролем, `ADMIN_ALLOW_HTTP=0`, `DEBUG_TOOLS=0`; необязательно `BALANCE_FILE=/opt/samopalka/data/balance.json`. Убедитесь, что пользователь процесса может писать в каталог данных. Сохраняйте каталог данных при обновлении релиза. Пароль не передаётся в клиентский код, сессии хранятся в памяти процесса, истекают через 8 часов или при перезапуске. 8 неверных попыток временно блокируют новые входы на 15 минут (ограничение общее на сервер). API без сессии не возвращает и не сохраняет настройки; запросы записи требуют специальный заголовок и cookie SameSite=Strict. Используйте один серверный процесс на один файл баланса.

При повреждённом файле баланса сервер не стартует, чтобы не сбросить настройки молча: остановите сервис, сохраните повреждённый файл отдельно и восстановите проверенный `balance.json.bak` (или удалите файл только если намеренно возвращаете весь баланс к исходному). Резервная копия содержит только предыдущую ревизию; для долговременной истории делайте внешние бэкапы.
