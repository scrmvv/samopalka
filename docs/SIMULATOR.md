# Game Simulator v1.1 — автоматические партии и аналитика

Симулятор использует **тот же серверный `BattleSession`**, что и браузерная игра. Никакие GPT/API-запросы для игровых ходов не выполняются. Тесты запускаются локально без игрового сервера, браузера и VPN.

## Запуск (Windows CMD или PowerShell)

Из корня репозитория:

```powershell
npm.cmd install
npm.cmd run simulate -- --games 100 --players 4 --seed 42 --strategy mixed --out reports/mixed.json
```

Для сравнения стратегий (нормальные правила боя):

```powershell
npm.cmd run simulate -- --games 1000 --players 4 --seed 42 --strategy aggressive --out reports/aggressive.json
npm.cmd run simulate -- --games 1000 --players 4 --seed 42 --strategy support --out reports/support.json
npm.cmd run simulate -- --games 1000 --players 4 --seed 42 --strategy random --out reports/random.json
```

При одинаковых `--seed`, `--players`, `--strategy`, `--mode` и версии игрового движка воспроизводится одна и та же последовательность. Для сравнения **разных версий** желательно сохранить тот же seed и настройки; изменение самих правил может изменить последовательность ходов, поэтому прямое совпадение партий не гарантируется.

## Новый режим: проверить всю кампанию до 6-го этажа

```powershell
npm.cmd run simulate -- --games 100 --players 4 --seed 42 --mode campaign-smoke --out reports/campaign-smoke.json
```

**Это намеренно искусственный режим:** герои получают 500 HP и усиленные ударные грани, а враги — по 1 HP. Он проверяет генерацию противников на всех этажах, переходы через привал и условие завершения шестого этажа. Исходы `campaign-smoke` **нельзя использовать для оценки баланса, классов, полезности артефактов или реальной сложности**. Обычные боевые правила и условия победы в `BattleSession` не меняются.

Если `campaign-smoke` не достигает 6-го этажа, это сигнал для расследования; возможны как ошибка движка, так и несовместимость сценария с новыми механиками. Для будущих наград и ролей добавьте их обработку к тестовому сценарию, не обманывая проверку принудительным `finish`.

## Что появилось в JSON-отчёте

- `meta.balanceComparable`: `true` только для стандартного режима.
- `totals`, `outcomes`, `highestFloorDistribution`: общая статистика (совместима с v1).
- `analytics.perGame`: урон по героям/врагам, лечение героев, урон от яда, поглощение щитом, число смертей.
- `analytics.firstHeroDeath`: средний шаг первой гибели, этажи и причины.
- `analytics.classes`: показатели по классам, лечение, полученный/нанесённый урон, смерть и победы, количество выбранных граней. `winRate` — процент появлений класса среди победителей (в обычном режиме преимущественно последний выживший), **не вероятность пройти 6 этажей**.
- `analytics.foes`: сколько раз противник появлялся, сколько реального урона героям нанёс, сколько раз убил героя. Сортировка по числу убийств.
- `analytics.statusesApplied`: число назначений состояний (не общее число тиков действия).
- `failures[].recentSteps`: последние 25 шагов с действиями и журналом, **даже без `--trace`**.

Урон и лечение считаются в **фактически изменённых HP**, а не по потенциальному значению кубика. Яд записывается отдельно. Щиты учитываются по количеству поглощённого урона. Смерть от накопленного яда приписывается сохранённому источнику эффекта, когда он известен. Если эффект наложен несколькими источниками или источника нет, точная атрибуция может быть неоднозначной.

## Как повторить ошибку

В поле `failures` будет указан seed и команда `reproduce`. Например:

```powershell
npm.cmd run simulate -- --games 1 --players 4 --seed 123 --strategy mixed --mode standard --trace --out reports/repro-123.json
```

Будет создан файл `reports/repro-123.traces.json` с подробными шагами. Для больших выборок `--trace` не рекомендуется: отчёты могут сильно вырасти.

Код завершения: `0` — ошибок не обнаружено, `1` — хотя бы одна ошибка/зависание, `2` — неверный параметр.

## Расширение после 3.4 и 3.5

Архитектура разделена на независимые компоненты:

- `apps/server/src/combatTelemetry.ts`: машинно-читаемые события расчёта урона, лечения и эффектов **из реального игрового движка**. Новая механика должна создавать свои события прямо там, где рассчитывается действие.
- `simulator/analytics.ts`: сбор статистики по героям и противникам. Новые показатели добавлять сюда, не разбирая русский текст журнала.
- `simulator/policies.ts`: стратегии ботов; при появлении выбора артефактов или ролей научить агента работать с новыми фазами.
- `simulator/scenarios.ts`: регистрируемые тестовые сценарии, пока `standard` и `campaign-smoke`. Каждому новому подэтапу можно добавить свой сценарий со строго обозначенными допущениями.
- `simulator/invariants.ts`: свойства, которые всегда должны выполняться, независимо от стратегий и баланса.
- `simulator/runner.ts`: виртуальные часы, seed, реальные методы `BattleSession` и последние 25 шагов при сбое.
- `simulator/cli.ts`: батч-прогоны и JSON-отчёт.

**Важное ограничение:** симулятор не проверяет интерфейс, CSS, корректность Socket.IO, а также не доказывает, что реализованные правила совпадают с PDF. Для новых эффектов нужны отдельные эталонные unit-тесты; для GUI — Playwright. Ноль найденных ошибок не равен отсутствию багов.
