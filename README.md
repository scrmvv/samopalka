## Этап 3.4-test — артефакты и грани кубиков

После зачистки этажа каждый герой сам нажимает кнопку броска `d6`, восстанавливает `2 + d6` HP, затем после бросков всех игроков по очереди выбирают артефакт из **четырёх** доступных (остающиеся варианты передаются дальше, предложения пополняются), либо отказываются в обмен на `+2` к максимальному HP или `+1` к одной грани. Выбор выполняется с каждого устройства; хост не может перейти дальше до завершения раздачи. На выбор награды даётся 60 секунд каждому участнику; по истечении времени автоматически присваивается +2 к максимальному HP. Замена грани вынесена в отдельное окно. Пустые стартовые стороны перенесены в конец карты кубика. Тестовый каталог — **97 карточек**, отобранных из листа «Артефакты»: простые и составные стороны с поддержанными эффектами, одна расходуемая лечебная реликвия, несколько бонусов и пассивных улучшений. В текущем тестовом каталоге артефакты не ограничены классом — тип из Excel показан на карточке, но ограничения по ролям не применяются до окончательной модели ролей.

См. [инструкцию для тестирования 3.4](docs/STAGE_3_4_TEST.md). Панель «ТЕСТ» включена по умолчанию в закрытой сборке (`DEBUG_TOOLS=0` отключает).

## Повторная партия (версия 3.3.3)

Когда игра завершится, хост может нажать **«Вернуть отряд в лобби»**. Все участники останутся в прежней комнате с тем же кодом приглашения и выбранными героями. Каждый подтверждает готовность, после чего хост начинает новую партию с первого этажа. При активном бое и на привале этот сброс недоступен. Новая игра автоматически очищает прошлые эффекты и результаты. Подробности: [docs/STAGE_3_3_3_TAUNT_AND_REPLAY.md](docs/STAGE_3_3_3_TAUNT_AND_REPLAY.md).

## Тестовая панель — включена по умолчанию для закрытого тестирования 3.3.3

При обычном `npm start` панель **«ТЕСТ» уже включена** и доступна только хосту запущенной партии. Хост может менять грани, HP, эффекты, противников и управлять бросками. Гости не могут пользоваться отладочными командами; проверки выполняются на сервере.

**Обязательно отключите её перед публичным размещением.** Для отключения задайте `DEBUG_TOOLS=0` и перезапустите сервер. В Windows CMD: `set DEBUG_TOOLS=0` → `npm.cmd start`; в PowerShell: `$env:DEBUG_TOOLS = '0'` → `npm.cmd start`; в Linux/macOS: `DEBUG_TOOLS=0 npm start`. Если хостом в публичной комнате может стать кто угодно, такой хост получит инструменты изменения игры, пока панель включена. Подробности: [docs/STAGE_3_3_1_DEBUG.md](docs/STAGE_3_3_1_DEBUG.md).

**Актуальная версия для закрытого тестирования: 3.4.2-test (15.11.2026) — исправления системы слов, последовательных ходов существ, поле без кругов, карточки монстров и адаптация размещения.**

> Это тестовая версия (MVP), а не законченная игра. Сборка 3.4-test добавляет раздачу поддерживаемых артефактов и улучшения кубиков. Полный каталог, роли и админка остаются следующими этапами. Чат пока является заглушкой. Игровые комнаты не сохраняются после остановки сервера.

## Быстрый старт для заказчика

Подробная пошаговая инструкция для Windows и macOS, обновления через GitHub и подключения друзей: **[docs/ЗАПУСК_И_ОБНОВЛЕНИЕ.md](docs/ЗАПУСК_И_ОБНОВЛЕНИЕ.md)**.

Нужно установить **Node.js 20.19+**, открыть терминал в папке с корневым `package.json` и выполнить:

```bash
npm install
npm run build
npm start
```

В Windows PowerShell при ошибке запуска `npm.ps1` можно заменить `npm` на `npm.cmd`.

Откройте **http://localhost:3000**. Сервер должен продолжать работать в терминале. Другие игроки могут открывать `http://IP_КОМПЬЮТЕРА_С_СЕРВЕРОМ:3000` при наличии доступа к той же локальной сети или подходящей VPN.

## Обновление через GitHub

Если проект уже получен командой `git clone`:

```bash
git pull
npm install
npm run build
npm start
```

Перед обновлением **остановите сервер** (`Ctrl+C`) и сохраните или закоммитьте собственные правки, чтобы `git pull` не конфликтовал с ними. После запуска создайте новую комнату и обновите браузер с очисткой кеша (`Ctrl+F5` в Windows, `Cmd+Shift+R` в macOS).

Если проект скачивался ZIP-файлом, скачайте свежий ZIP репозитория и распакуйте **в отдельную папку**, затем выполните команды первого запуска. Не смешивайте старые и новые исходники.

## Что добавлено в 3.3

- Применение дополнительных слов и статусов рассчитывается **на сервере** и синхронизируется с игроками. На поле и в панели ресурсов показываются активные эффекты.
- **Яд** наносит периодический урон и игнорирует щиты. **Слабость** снижает значения сторон кубика на ход. **Сон** и **оглушение** могут блокировать ход. **Паралич** добавляет «Боль» к следующему действию.
- **Уворот, Броня, Прочность и Бесплотность** по-разному уменьшают входящие атаки. Реализованы свойства **«Позади»**, **«Дальность»**, **«Разброс»**, **«Издыхание»**, **«Пиявка»**, **«СамоЛечение»**, **«Чума»**, **«Гниение»** и выбор целей.
- Исправлена стартовая грань Берсерка: **«СамоУворот 1»**, а не «Самооборот». Для Рыцаря подключены **Самощит + Насмешка**; Лучник использует дальность.
- Реализованы указанные в таблице массовые атаки, некоторые призывы, перемещение монстров, смерть Миазма после атаки, эффекты после смерти и призыв Лича при половине здоровья.
- Монстры теперь используют указанные на карточках значения атак вместо временной универсальной единицы урона.

**Подробная документация, ограничения и порядок проверки:** [docs/STAGE_3_3.md](docs/STAGE_3_3.md). Исправления предыдущего этапа сохранены; их описание есть в [docs/STAGE_3_2_HOTFIX.md](docs/STAGE_3_2_HOTFIX.md).

## Что пока не входит в 3.3

Механики из словаря, которые появляются исключительно на артефактах или улучшенных кубиках (например, «Финт», «Рост», «Энергия», «Усиление», «Очищение»), частично реализованы в тестовом подэтапе 3.4: поддерживаются только проверенные комбинации. Временные и сложные словесные модификаторы, весь каталог из таблицы и скрытые роли пока не реализованы. Отдельные сложные взаимодействия требуют дальнейшей совместной проверки баланса и трактовок.

Чат пока является заглушкой. Партии не сохраняются на диск. Локации исключены из MVP; текущие боссы выбираются случайно в пределах этажа.

## Сеть и таймеры

По умолчанию сервер слушает **0.0.0.0:3000**, поэтому подключение возможно по локальному IP хоста, через Radmin VPN или другую VPN с разрешённым обменом между участниками. Для игры по сети должен быть открыт входящий TCP-порт 3000 в брандмауэре. **Не открывайте тестовый сервер в публичный интернет без дополнительной защиты.**

В этой демонстрационной сборке таймеры выставлены на **60 секунд**. Чтобы проверить согласованные значения **15/5**, перед запуском сервера задайте переменные окружения:

**PowerShell:**
```powershell
$env:TURN_SECONDS = '15'
$env:SHORT_TURN_SECONDS = '5'
npm.cmd start
```

**macOS/Linux:**
```bash
TURN_SECONDS=15 SHORT_TURN_SECONDS=5 npm start
```

Настройка применяется при создании новой партии. Окно переподключения остаётся 60 секунд.

## Техническая структура

```text
apps/client/        React + TypeScript + Vite — интерфейс
apps/server/        Node.js + Express + Socket.IO — комнаты и игровая логика
packages/shared/    Общие игровые типы и конфигурация героев
docs/               Инструкции, ограничения и сценарии проверки
```

Команды разработчика: `npm run build`, `npm test`, `npm run dev:server` и `npm run dev:client` (два последних — в разных терминалах).

**Проверки:** предыдущие версии 3.3.3 и Simulator v1.1 проходили серверные автотесты и игровые прогоны. Данная упаковка включает дополнительную проверку режима по умолчанию. Полную сборку `npm.cmd run build`, `npm.cmd test` и совместный запуск с друзьями выполните на машине хоста перед распространением. `package-lock.json` отсутствует: при первом `npm install` npm создаст его локально.

## Автоматическое тестирование партий

В комплекте есть локальный симулятор на настоящем боевом движке. Команда: `npm run simulate -- --games 100 --players 4 --seed 42`. Инструкция: [docs/SIMULATOR.md](docs/SIMULATOR.md). Игровые ходы не требуют доступа к ИИ.


### Автотестирование (Simulator v1.1)

```bash
npm run simulate -- --games 1000 --players 4 --seed 42 --strategy aggressive --out reports/aggressive.json
npm run simulate -- --games 100 --players 4 --seed 42 --mode campaign-smoke --out reports/campaign-smoke.json
```

Режим `campaign-smoke` намеренно усиливает героев и ослабляет монстров **только для проверки 6 этажей**. Для анализа баланса используйте обычный режим без `--mode`. Подробнее: `docs/SIMULATOR.md`.
